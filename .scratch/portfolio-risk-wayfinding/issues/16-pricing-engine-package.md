# Pricing engine package (`packages/pricing-engine`)

Type: task
Status: resolved

Blocked by: none (builds on [06](06-pricing-inputs-and-models.md), [ADR 0001](../../../docs/adr/0001-own-pricing-model.md) and [ADR 0007](../../../docs/adr/0007-pricing-engine-is-a-python-worker.md)). Followed by [17](17-engine-rate-and-dividend-inputs.md) (rate and dividends) and [18](18-engine-worker.md) (worker).

## Goal

Build the scaffold and the pricing core of the one engine that the app's server and the `schwab` CLI ([14](14-schwab-option-price-cli.md)) both use, as a standalone Python project with its own tooling. Every price names its inputs. This package does no network I/O.

## Layout (from ADR 0007)

- `packages/pricing-engine/` is a standalone `uv` project: its own `pyproject.toml`, ruff (lint and format), pytest, and a type checker. **Choose the type checker here** (ty, pyright or mypy) and record it in the package `AGENTS.md`. QuantLib has no type hints, so the checker covers our code only.
- A thin `package.json` wraps `lint`, `format:check`, `typecheck` and `test` as scripts that run through `uv run`. Add `packages:` to `pnpm-workspace.yaml` so `pnpm -r` reaches it. pnpm manages no Python dependencies.
- Lefthook: ruff on staged `*.py` at commit; type check and pytest at push, beside the existing jobs. Check that Knip copes with a `package.json` that has no JS sources and fix its config if not.
- Add `packages/pricing-engine/AGENTS.md` and list it under "Read next" in the root `AGENTS.md`.
- The CLI's path dependency on the engine is added in [14](14-schwab-option-price-cli.md), not here.

## Scope

1. **Settlement instant.** A function from OCC root and expiry date to a timezone-aware instant: 16:00 `America/New_York` for equity, ETF, SPXW and XSP; 09:30 for AM-settled SPX. An unknown root is an error, not a default. Daylight saving changes between now and the expiry must be correct.
2. **Virtual clock.** Convert calendar minutes to the Settlement instant into a 3,650-day virtual clock and rescale σ, r, the continuous yield and dividend times: `σ' = σ√(T/T_ql)`, `r' = r·T/T_ql`, `q' = q·T/T_ql`, dividend day = `round(t_d/T · N)`. Reference: `tools/schwab/prototype/quantlib-engine/spike_intraday.py` on branch `prototype/quantlib-engine`.
3. **Inputs.** Every price takes spot, σ, rate, continuous yield (default 0), discrete cash dividends (a dated list, default empty) and borrow rate (default 0, flagged on the result when the Underlying is hard to borrow). Each input carries a provenance string (`from`) that the result echoes.
4. **European** pricing: Black-Scholes-Merton. Index options take an explicit forward. A helper derives the forward from put-call parity, `F = K + e^{rT}(C − P)`, from a call Mark and a put Mark at the same strike and expiry; the caller supplies the Marks from the chain.
5. **American** pricing: QuantLib `FdBlackScholesVanillaEngine` with each dividend as a cash drop. A call on a non-dividend payer with no borrow cost uses the closed form. Default grid 100 by 200 for single prices; 50 by 100 is acceptable for the Shock grid. Include the Leisen–Reimer tree on spot minus the present value of dividends (odd step count, about 101 to 201) as a cross-check.
6. **Mark-implied IV** solved from a **Mark** through the model (Brent on the price function, σ bounds 0.01 to 5.0 as a decimal). When the Mark is at or below intrinsic, or no σ brackets it, return no IV, a reason (`at_or_below_intrinsic` or `no_bracket`), and the residual (Mark minus the model value at the lowest bound). [ADR 0001](../../../docs/adr/0001-own-pricing-model.md) carries that residual unchanged under Shocks.
7. **Greeks:** delta, gamma, vega, theta, rho, all by bump-and-reprice so they share one code path. Units: vega per vol point, theta per calendar day, rho per percentage point of rate. Test delta, gamma and theta against the engine's own values.
8. **Schema.** Pydantic v2 request and result models for the above (contract, inputs with provenance, price result with IV, greeks, flags). Commit the exported JSON Schema under `packages/pricing-engine/schema/`; the server generates its TS types from it.

## Acceptance

From the spikes (`tools/schwab/prototype/quantlib-engine/VERDICT.md`):

- Haug's Black-Scholes-Merton table value 2.1334 (S=60, K=65, T=0.25, r=8%, σ=30%) to four decimals.
- European prices equal closed-form Black-Scholes-Merton at the exact fractional T to 1e-9, for T from 3.5 hours to 2 years.
- American, no dividends, equals a 4,000-step CRR tree at the exact T within 0.1 cent at 100 by 200 and within 0.05 cent at 400 by 800, for T of 3.5 hours, 1.5 days and 30 days.
- American with two cash dividends is stable to 0.05 cent as the virtual clock grows from 730 to 36,500 days.
- Mark-implied IV recovers the generating σ to 1e-4 vol points on both fixtures (a 103% call and a dividend-paying in-the-money put).
- The parity-forward helper recovers a known forward to 1e-9 from prices generated by the model.
- Settlement instants are correct on both sides of a daylight saving change (the 2026-11-01 fall-back is a fixture) and for AM-settled SPX.
- Schema export is deterministic and a test fails when the committed schema is stale.
- The 50-Position by 100-Shock grid completes in under 1 s on this laptop through a process pool (a benchmark script, not a unit test).
- No test needs the network.

## Answer

Landed in `4c024dc`: `packages/pricing-engine/`, a standalone `uv` project with the pnpm wrapper, Lefthook jobs, Knip config and `AGENTS.md`. The type checker is ty. Settlement instants, the virtual clock, inputs with provenance, European and American pricing, parity forward, Mark-implied IV, bump-and-reprice Greeks and the committed JSON Schema are all in. Checked on 2026-10-24: 85 tests pass, Ruff and ty are clean, and the 50-Position by 100-Shock grid takes 0.12 s through a 14-process pool against the 1 s limit. No test uses the network.

The pricing details are in `packages/pricing-engine/AGENTS.md`. The comparison with Schwab is in `docs/research/pricing-engine-vs-schwab-iren.md` (`be9a9b5`): IV runs 0.7 to 0.8 vol point above ours on long-dated IREN calls, and short-dated, low-priced options are noisier.

Open items:

- Dividend-paying American options have not been compared with Schwab, and are expected to differ more.
- The package says it does no network I/O, which [17](17-engine-rate-and-dividend-inputs.md) changes for the Treasury module.
